# Review, 2026-10-03 — plan against outcome

A point-in-time catch-up, not a current-state doc. Dated so it cannot quietly
become stale and be read as live. Current state is `CLAUDE.md` plus each
family's `STATE.md`; the reasoning behind any line here is in the ledgers.

Scale: 48 commits, 11,385 lines of Python, 4,290 lines of documentation, 218
tests that run in five seconds with no models. Five seats, 59 settled ledger
entries including six dated corrections, 14 HANDOFF sections.

---

## What the project actually does, today

Give it a baseline system **A** and a candidate **B**, both of which emit text.
It reports which inputs changed behaviour, with a false-alarm rate it can
defend, **without being told what any output means**.

The trick is in the name. Before comparing A to B it runs A **twice**. The
second baseline run, A-prime, is a comparison where nothing changed, so the
spread between A and A-prime is the system's own run-to-run noise. That is the
null distribution, and every threshold is set from it rather than guessed.

Concretely, a run is:

1. **Record** three arms over the same inputs, interleaved, k samples each.
2. **Dedup and normalise** — strip presentation, never content.
3. **Cluster** each input's outputs into semantic modes, by asking an NLI model
   whether two outputs entail each other in both directions.
4. **Score** five channels: mode-share distance, dispersion, novel-mode mass,
   NLI contradiction, NLI directional entailment (two-tailed).
5. **Select** per channel by target-decoy FDR, stratified by output shape.
6. **Check** structural rules induced from the baseline and pruned by the decoy
   arm.

Two properties matter more than any channel. **Every channel is scored against
its own decoys**, so a broken channel produces noisy decoys, raises its own
threshold and reports nothing instead of nonsense. And **no channel votes** —
findings are reported per channel, never summed, because combining them needs
weights and fitting weights outside a fold is what MTH-009 forbids.

The second deliverable is the study: does any of this survive being moved to a
domain it was not built for? Nobody has published an answer (STD-005).

## The plan, and what happened to each piece

The original shape was five weeks: week 0 probe the channels, week 1 build the
recorder and the statistics, week 2 compose the detector, week 3 titrate
severity, week 4 produce the transfer matrix.

### Done as planned

| Piece | Where |
|---|---|
| Probe suite and blind-spot map measured | week 0, MTH-011 to MTH-017 |
| Three-arm recorder, interleaved, resumable | ENG-001 |
| Target-decoy FDR, validated on ground truth | MTH-018 |
| Provenance: run id, config hash, git state, pinned revisions | week 1 |
| Semantic mode clustering, threshold fitted | MTH-020 |
| Induced structural conformance, decoy-pruned | STD-003 |
| Fault taxonomy frozen before any detector tuning | BCH-003, BCH-011 |
| Detector composed end to end | week 2 |

### Improved beyond the plan

**The channel inventory was measured rather than assumed, and the plan was
wrong.** The design expected embedding displacement to be the primary channel.
It is **anti-correlated with meaning change** and is now gated behind a
surface-stability check (MTH-011, MTH-012). NLI carries the load instead
(MTH-013). Replicated across three embedding families, so it is a statement
about embeddings and not about one checkpoint.

**Register became a third probe class, and recovered a signal.** The false
alarms the design blamed on `verbosity` were never false alarms: the channel was
correctly detecting a change we had mislabelled as a non-change. Relabelling
also moved the clustering fit's argmax from 0.05 to 0.65, converging on the
threshold MTH-020 had chosen by argument alone (MTH-021).

**Omission was closed by a second reading of the same model.** Contradiction is
structurally blind to content that is simply missing (MTH-014). Directional
entailment, signed and two-tailed, closes it — and the sign names the fault:
positive means information removed, negative means added (MTH-016, MTH-022).

**Eight tools instead of two.** Owner's call, against the original two-tool
sketch, on the grounds that real agents are integrated and light agents make a
bad baseline for a study that will be read later. Then measured: all three 8B
models selected correctly 16 times out of 16, and the schemas cost 461 to 751
prompt tokens rather than the 1,200 to 2,000 assumed (BCH-013). The richer
design cost nothing.

**Long runs became pausable.** Not in the plan at all. Added once recording was
measured as the binding constraint, so a study can be left running overnight and
stopped by asking (HANDOFF §14).

### Tweaked to fit the problem better

**A `reader` seat was added.** The README assumed knowledge no first-time reader
has, in the owner's words "too cryptic... very identifiable AI typos". The fix
was structural rather than a rewrite: a seat forbidden from assuming project
context, owning an audience contract, with a prose checker as an instrument
(RDR-001 to RDR-004, HANDOFF §11).

**The sampling seed was deliberately cut out of the pinned-instruments rail.**
Pinning every parameter for reproducibility destroys the one thing the method
needs free: two baseline arms on the same pinned seed collapse onto the same
outputs, and the decoy arm is the null. Reproducibility now means the seeds are
*known*, not *equal* (MTH-023, HANDOFF §13).

**The agent output format is kept non-compliant on purpose.** It obeys its own
format rule 4 times in 12 and its outputs span 11 to 396 words. The owner
rejected narrowing the bench to fix that: real agents are heterogeneous, and a
tool validated only on well-behaved synthetic agents invites exactly the
criticism that it does not apply to production. Whether detection survives
output heterogeneity is now a measured axis rather than a design constraint
(BCH-015, HANDOFF §13).

**`palworld-rag` was split into its own repository** and excluded from the
headline transfer numbers, because it is the development system and including it
would measure the detector against the system it was built on (HANDOFF §3).

**A cell's `mode` became its `output_format`.** One word meant two unrelated
things — a cell's output format, and a semantic mode in an output cloud — and
the collision confused the owner, which is evidence rather than bad luck.

### Discarded

| Dropped | Why |
|---|---|
| Three-way triage: benign / regression / improvement | Unidentifiable without labels (MTH-001) |
| Normalised displacement ratio | No null distribution (MTH-002) |
| Mean-and-spread summaries | Blind to the changes that matter (MTH-005) |
| Exact-match clustering as the detector's default | Saturates on any text-modifying fault; the first titration reported 100% recall and measured only whether the string changed (ENG-002) |
| The 16k context cap | Cost 3-4x and defeated its own purpose (BCH-008) |
| "Noise floor" as the headline framing | Partially occupied by prior work (STD-001) |
| Metamorphic relations, embedding triage | Already solved or half-occupied; not claimed (STD-002, STD-004) |
| Fine-tuning | Deferred out of this project entirely, to a later third project (HANDOFF §4) |

## Findings that matter, graded by how many independent derivations support them

### Several derivations

**Embedding displacement is anti-correlated with meaning change** (MTH-011).
Replicated across three embedding families, which makes it a property of
embeddings rather than of one checkpoint. This inverted the design's channel
ordering.

**NLI findings are checkpoint-dependent** (MTH-017). A second checkpoint from a
different family reproduced the *direction* of every finding and **none of the
magnitudes**, with gaps up to 48 percentage points. Anyone reusing this must
re-measure with their own judge. It is in the README's honest limits.

**FDR control works on ground truth** (MTH-018). Realised false-discovery rate
0.034 against a 0.10 budget, 93% recall, on a stub where the answers are known.

**Seed determinism is unstable, and three measurements disagreed.** BCH-012 found
byte-identical output under a repeated seed on four models. A later measurement
found 2 distinct outputs in 8 repeats, and another found substantive divergence.
The difference tracks whether other requests ran in between, so **which cluster a
pinned-seed run lands in appears to depend on server cache and batch state** —
not a study variable, and not in provenance. The disagreement is the finding, and
it is unresolved (MTH-023 and its correction).

### One derivation, strong

**The detector separates a real fault cleanly** (ENG-007). On a stale knowledge
base, three channels that are not variants of each other — mode-share,
novel-mode, NLI contradiction — each put **zero decoys** above their best cut.
Confirmed with no models at all: where the fault fired, A-to-B text similarity
was 0.593 against A-to-A-prime at 0.776; where it did not fire, 0.846 against
0.815.

**Two channels are blind to that fault class, and should be.** Dispersion
measures spread within a cloud and a stale value shifts a cloud without widening
it. Directional entailment is built for content removed or added, and a
substituted value is neither. **The decoy arm made both report nothing rather
than noise**, which is the property the whole composition was designed for, and
this is the first time it has been demonstrated on real outputs.

**The estimator cannot report fewer than `1/q` findings** (MTH-024). Arithmetic,
not sampling: the Barber-Candes correction makes the estimate
`(1 + decoys_above) / targets_above`, so with zero decoys the best possible
estimate is `1/targets_above`. At q=0.10 **nothing is reportable until ten inputs
are selected.** ENG-007's run had nine. The product consequence is sharper than
the study one and is now in the README: *the tool cannot report a single changed
input*, and an empty report means "fewer than ten changed", not "nothing
changed".

**Recording dominates cost, not detection.** 589 seconds recording against 10
seconds detecting. The long-standing worry that the equivalence predicate would
be the dominant expense is wrong by about two orders of magnitude. The full
nine-cell factorial is **17.3 hours** for one candidate system, of which the
agent format alone is over half.

**Per-input activation is a first-class experimental parameter.** A stale view
only matters where the stale value differs from the true one. Staling one tool
fired on 2 of 12 inputs; staling the four readable tools fired on 15 of 30. At
the low rate, the run was **arithmetically incapable** of reporting anything
before it started (BCH-014, MTH-024).

### One derivation, weak, and flagged as such

**A conformance invariant is draw-dependent** (ENG-009). Shifting the stub's
random draw by three invocations made `word_count_range` fire on 2 of 200
unchanged outputs. The test passes 5 of 5 on one draw and fails on the other, so
its pass was draw-dependent and nobody knew. This qualifies ENG-005 rather than
overturning it, and it is one draw rather than a measured rate.

## Three mistakes worth keeping on the record

**Variation was repeatedly treated as noise when it was the phenomenon.** The
seed case is the starkest: the method is named after the arm whose only job is to
vary, and a rule was still proposed that would have flattened it. Output
heterogeneity was the same error in a different costume. In both cases the owner
corrected the framing.

**Summaries were read where distributions were needed.** `0 flagged` and
`240/240 complete` both concealed their opposite. The project's own discipline —
ask for the instrument, not the summary — exists for exactly this, and had to be
rediscovered twice in one session.

**Work was duplicated without grepping first.** Bespoke activation
instrumentation was written while `faults.py` already had an `ActivationLog`,
and the bespoke version recorded per input where the existing one records per
sample, which silently collapses the request-level and per-principal rates that
blast regimes B2 and B3 exist to distinguish.

A fourth, structural one: **eight times a hand-written test double was more
cooperative than the real API**, and every divergence cost a live run to find.
Fixtures are now captured from a real server, and the capture found two more
divergences within a minute of first running — one of which was a live bug, not
a test artifact.

## Where it stands

The tool works, on a real system, demonstrably. The study has not started: no
cell has been through the detector at a size that could report anything, and the
headline figure needs 17 hours of GPU that has not been budgeted or spent.

The honest summary is that the **engineering is well ahead of the evidence**.
Nine months of ledger discipline has produced a detector whose every channel is
measured rather than assumed, a harness that grades on activation rather than
labels, and three layers of guard against the specific ways this kind of run
fails silently. What it has not produced is a single number that answers the
question on the paper's title page. Everything between here and that number is
GPU time and the patience to write it up.
